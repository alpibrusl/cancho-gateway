The evidence

What each test covers, what it found, how each number was measured, and what is not claimed. Every figure here is reproduced by a command in the repository; where a claim turned out false, the document that made it was corrected in place.

What is claimed, and what is not

Claimed, and measured

  • Requests with ambiguous framing are refused, each with a rule, against a corpus of 60 head cases and 39 chunked-body cases.
  • No input in 3,000 fuzzed heads and bodies reaches a trap.
  • Routing agrees with an independent reference on 4,800 generated requests.
  • Header behaviour agrees with nginx 1.24 except where a table says why not.
  • The program touches no files and makes no foreign calls, as the compiler reports.

Not claimed

  • That the compiler proves the upstream set. It cannot narrow outbound addresses yet; the set is enforced in code and tested.
  • That it is fast. It is slower than HAProxy on four of five cells and than nginx on POST bodies.
  • That it is safe on the public internet: no TLS, no independent security review.
  • That the smuggling corpus is complete: it comes from RFC 9112 and one 2019 paper. The llhttp and nginx test suites have not been consulted, and framing has no differential against nginx (headers do).

Request framing

Run with python3 tests/smuggling/run.py against the pinned compiler.

60head cases, each with the bytes, the expected outcome and its source
39chunked-body cases, each delivered whole and in pieces of 1, 2, 3, 5 and 7 bytes
2,494proper prefixes of the corpus: an accepted head’s are all “more”, a refused head’s are never accepted
1,500 + 1,500seeded mutations of heads and of chunked bodies: 0 traps, no delivery disagrees with another

The corpus was run against the compiler’s own HTTP parser first, before any framing code existed. It already refused 54 of the 60. The six gaps were duplicate identical Content-Length, a repeated Transfer-Encoding: chunked, absolute-form targets, GET *, CONNECT, and a head of up to 64 KiB.

Stricter than the RFC on purpose, each a known smuggling lever: chunk extensions are refused, trailer fields are refused, no whitespace around a chunk size, a size of more than eight hex digits is refused, and a declared chunk larger than the route’s limit is refused at its size line, before any data is read.

Mutants shown killed: extensions ignored, size digits unbounded (the unbounded version traps on a 17-digit size), the body limit unchecked, trailers accepted. One mutant survived the first corpus (the CR check after chunk data); a case was added that kills it.

Routing

The host picks the route set, then the longest segment-boundary prefix that allows the method; a tie is refused when the deployment is generated. tests/route_test.py builds random deployments, compiles each into a probe and compares 4,800 requests with an independent Python reference, plus 18 fixed cases. Paths that name one resource two ways are refused (//, . and .. segments, an escaped dot, slash or backslash, a malformed escape).

The proxy against real sockets

tests/proxy_test.py: 75 tests, about a minute, a real gateway and upstreams that hang, reset, lie, close mid-response and send responses with two lengths. They cover, among others:

  • a slow client that never finishes its head, while others are served;
  • a stalled upstream, a stalled client, a client that leaves mid-body or mid-response;
  • 6 MiB through queues of 32 KiB to a client that reads late and in dribbles, with the digest compared; six concurrent 12 MiB downloads, so that a queue overrun would corrupt a neighbour;
  • bodies by Content-Length and chunked, split at every few bytes;
  • a dead pooled connection: a GET is sent again once, a POST never; a retried request keeps its request id;
  • an upstream that flaps, and the circuit with its single half-open trial.

Each piece was mutation-tested as it was built: the proxy core, the pool and the circuit, the header policy (29 mutants) and the access log (32). Survivors were either strengthened tests or documented equivalents. Each document under docs/ lists them.

Headers against nginx

tests/headers/differential.py, run in CI: 19 cases, each on a default route and on a trusted one, with three request targets each, sent to nginx 1.24 and to the gateway in front of the same recording upstream. 114 comparisons, 36 differences, every one in a table with its reason; an unlisted difference fails, and so does a listed one that stops differing.

They agree

  • Order, case, duplicates and values of ordinary headers
  • An empty value, a 4,000-byte value, bytes above 0x7f
  • Keep-Alive, TE, Upgrade: both remove them
  • The request line, with a query and escapes

They differ, on purpose

  • Proxy-Authorization, Trailer, Proxy-Connection, and a header named by Connection: nginx forwards them, the gateway removes them (RFC 9110 7.6.1)
  • Forwarding claims and a client’s request id on a default route: the gateway does not believe them
  • The gateway appends its own Via

The first run of this test showed four of the design’s assumptions about nginx false (it also removes Keep-Alive, TE and Upgrade, and forwards an empty value); the table and the design document were corrected to what was measured.

The access log

  • One line per request, bounded at 768 bytes (the worst line, every field at its cap, measured 676), the path escaped and cut, no query string.
  • A full pipe, measured: with stdout a pipe nobody reads, 320 to 336 requests were answered before the loop blocked in its write. When the reader returned, every line arrived in order, none dropped. The log is not silently lost, and a stalled reader stalls the gateway.
  • A hundred clients leaving together overflow a 1,600-byte queue (the real one is 256 KiB, which a turn cannot fill): lines are dropped, counted, and the count is announced in the log, with lines + announced == requests exactly.
  • With stdout on /dev/full the gateway stops with status 6 (log_failure = "exit", the default) or keeps serving ("continue").
  • Cost, paired against the build before: 3–5% of throughput (C1 0.95, C4 0.97).

Metrics and health

  • An optional second port (admin_listen): /metrics (JSON, or Prometheus text with ?format=prometheus), /healthz and /readyz, which says why it is not ready (an upstream’s open circuit, a failing log) as data. Read only, a 2 KiB head, at most 8 connections, 2 s for the whole exchange; everything else is a refusal with its own rule.
  • The counters equal an independent count: over a varied run, the route, status class, bytes, duration histogram and refusals-by-rule in /metrics are exactly what the gateway’s own access-log lines add up to.
  • The largest answer a deployment can give has a stated size (metrics.worst_case()), the buffer is that size, and a unit test fills every counter to its brim and checks the answer fits and the bound is within 10% of it, on a deployment with 3-byte names and one with 32-byte names.
  • Cost of the counters, paired against the build before in the same rounds: C1 1.02 (0.96–1.18), C4 0.97 (0.93–1.08): nothing the noise does not hide.
  • 42 mutants of the new code: 40 killed, 2 argued (one needs a partial write that a loopback socket cannot be made to give; one is an unreachable branch). The admin port listens on every interface (the compiler offers no loopback-only bind) and has no authentication: it shows route and upstream names and counters, nothing about a request, but firewall it.

The benchmark

Protocol fixed before any number (docs/bench.md), run by bench/run.py, raw results in bench/results/.

  • One shared 4-core VM, over loopback. The proxy under test is on core 0, the upstream (nginx, two workers) on core 1, the load generator (wrk, 2 threads) on cores 2 and 3.
  • Six cells; 5 interleaved runs of 10 s after a 3 s warm-up, the proxy restarted for each; median, min and max. Each proxy answers three sanity requests first. No run had a non-2xx response or a socket error; none was client-bound (wrk at most 78% of its cores) or upstream-bound (at most 54%); the proxy was at 95–99% of its core in every throughput cell.
  • Versions: nginx 1.24.0 and HAProxy 2.8.16 (Ubuntu packages), Envoy 1.39.3 (from its image), Caddy 2.6.2 (older than current), Traefik 3.6.0 (built from source without its UI), Kong 3.9.3 (DB-less, from its image). Configurations are in bench/conf/; each is a plain reverse proxy with keep-alive to the upstream, no access log, one worker. Pingora was not run.
  • This is the second run. The machine was slower than in the first (nginx’s own C1 throughput went from 43k to 30k requests/s) and the gateway’s did not fall as far, so its ratio to nginx on C1, C1b and C3 differs between the runs (0.80 then 1.15 on C1) and is not a finding. What held in both: the 16 KiB POST (0.42 then 0.47 of nginx, 0.54 then 0.55 of HAProxy), the 64 KiB response against HAProxy (0.53, 0.54), and the win with Connection: close (1.49 then 2.08 against nginx).
  • The gateway has no client keep-alive: its client connections close after each response, so most cells make it accept and close a connection per request while the others reuse one. That, not tuning, is most of the remaining gap: 11 system calls per request against about 5 for nginx and 4 for HAProxy.

What the tests found

In the order they were found. Each was fixed with a test that fails without the fix.

Found byWhat was wrong
First proxy testsA blocking listener hung in accept and stalled every client; it is non-blocking now.
A 413 testA refusal was followed by a TCP reset that destroyed it before the client read it. The gateway now lingers (500 ms of silence, 3 s at most) before closing.
Close-delimited responsesA response that ends when the upstream closes, or one already flushed, hung until the total deadline.
An early responseA response that arrived before the upload finished reset the client mid-upload.
The route referenceA division by zero on an unknown method: a trap reachable by any client. The guard was reordered.
The circuit testsA request refused locally used up the single half-open trial, so the circuit could not close. The circuit check now runs last.
The benchmark’s first runA 16 KiB POST reached the gateway as a 16,384-byte read and a 96-byte read; the second write waited about 43 ms for a delayed acknowledgement on most requests. TCP_NODELAY is set now.
Probes of the compilerFour assumptions were false (the upstream set can be proved: one bound serves listening and connecting; a client address exists; the compiler has randomness; what nginx forwards), and one fact was found: writing to stdout blocks the whole loop when its reader stops. Each design document was corrected in place.

Not tested, not built

  • No soak: a long run with faults has not been done. Short-lived tests are all there is.
  • No independent review of the parsing; the corpus is the authors’.
  • Not built: authentication, rate limiting, TLS (designed, not built: docs/tls.md). WebSocket is built as a byte tunnel, and the gateway reads no frame (docs/websocket.md).
  • One core, about 127 concurrent sessions, no client keep-alive.
